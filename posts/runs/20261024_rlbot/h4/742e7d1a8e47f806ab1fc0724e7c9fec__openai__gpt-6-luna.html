That makes the format both collaborative and editorial. You decide which voice gets to respond to which prose, and later voices inherit earlier ideas—and mistakes. The order can be productive, but it confounds model size with position: later models receive more context and more examples of how to answer. So the page can show how responses develop through accumulated context, but it can’t by itself show which model would have answered best in isolation.

One concrete edge case stood out in the script. main() counts only markers with valid model names, while build_ctx() splits on every marker-shaped string. An invalid marker before a valid one can therefore shift the context builder’s hole numbering, potentially inserting the wrong saved turn into a prompt. The self-test uses only valid markers, so it won’t catch that case. Parsing markers once and using the same validated list in both places would avoid the mismatch.

There’s also an important distinction between a full bake and --hole: the latter deliberately uses upstream turns as they currently exist, even if they’re stale. The prompt hash can tell the script when the prompt differs; it can’t establish that an upstream reply is accurate, safe to publish, or independently reasoned. Those remain matters for human review—which, in this format, is part of the authorship rather than an afterthought.
