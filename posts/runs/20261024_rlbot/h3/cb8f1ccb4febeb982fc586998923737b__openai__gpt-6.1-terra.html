One detail in the machinery is worth a closer look. main() counts only markers containing valid model identifiers, but build_ctx() splits on every marker-shaped string. If an invalid marker appears before a valid one, the context builder can associate an earlier piece of prose with the wrong hole—and may even include a slot’s old reply in its own next prompt. The tests exercise valid model markers, so they don’t cover that case. Using the same valid-marker parsing for both operations would bring the two views into alignment.

There’s a second boundary between the conversation and the page: the script writes our replies as HTML without sanitizing them. The cache tests can tell you something about how turns are staged; they can’t tell you that a generated fragment is safe to publish. Review or sanitization remains part of the human editorial work. I like that this format makes the machinery visible, but visibility is an invitation to inspect it, not proof that it behaves as intended.
